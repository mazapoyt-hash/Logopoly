# CoinScope

Сканер криптовалют, который выдаёт сигналы **Лонг / Шорт** с уровнями входа,
стопа и тейка — и **честно считает, чем каждый сигнал закончился**.

## Про «точность» — сразу и прямо

Никакая система не предсказывает рынок с гарантированной точностью. Если бы
предсказывала, её бы не продавали, а тихо использовали. Поэтому здесь слово
«проверенный» означает ровно одно:

- каждый сигнал проходит **бэктест по истории** без подглядывания вперёд;
- каждый выданный сигнал **отслеживается вживую** до стопа или тейка;
- на сайте показывается **фактический результат**, включая убытки, а не
  заявленный винрейт.

Статистика считается одними и теми же правилами для истории и для живых
сигналов, поэтому цифры сопоставимы. Винрейт не выносится в заголовок, пока
сделок меньше 20 — на малой выборке это шум, а не доказательство.

### Текущий результат: преимущества нет

На реальных данных Binance (8 монет, 1h, ~500 свечей) стратегия **убыточна**:
104 сделки, винрейт 33%, средний результат −0.26R, profit factor 0.67,
суммарно −26.7R. Проверка на устойчивость даёт вердикт **«fragile»** — из 96
наборов параметров прибыльны 3 (3%), и все три стоят в углу сетки с profit
factor 1.06–1.13, то есть на уровне шума. Это не проблема настройки порогов:
преимущества нет у самого подхода.

Поэтому на вкладке «Сигналы» над карточками висит предупреждение с этими
цифрами. Карточки не убраны — движок работает и должен показывать то, что
выдаёт, — но смотреть на них, не зная измеренного результата, нельзя.

**Это не финансовая рекомендация.** Инструмент технического анализа.

## Что уже работает

**Живые данные биржи**
- По умолчанию источник — **Binance** (публичные endpoint'ы, без ключей и ордеров).
- Цены опрашиваются каждые ~10 секунд одним пакетным запросом на все монеты.
- Открытые сигналы закрываются **по текущей цене**, а не по закрытию свечи —
  так же, как бэктест считает, что стоп внутри свечи исполнился.
- Если биржа недоступна, сервер прямо об этом пишет и не притворяется рабочим.

**Сигналы**
- Конфлюэнс-движок: тренд (EMA 21/50/200), импульс (MACD), сила тренда (ADX/DMI),
  перегрев (RSI), объём, подтверждение старшим таймфреймом.
- Фильтр флэта: при ADX ниже порога сигналов нет вообще.
- Стоп по волатильности (ATR), тейк по заданному соотношению риск/прибыль.
- В карточке явно указано, **на каком уровне фиксировать прибыль и убыток** —
  цена, процент движения и результат в R.
- **Вероятность успеха** с доверительным интервалом и размером выборки.
- У каждого сигнала — score 0–100 и список причин человеческим языком.

**Проверка**
- Бэктест по всем монетам: винрейт, средний R, profit factor, сумма R, просадка.
- Живой трек-рекорд опубликованных сигналов.
- Комиссия и проскальзывание вычитаются с обеих сторон сделки.
- **Проверка на устойчивость** (`npm run validate`) — две отдельные проверки,
  и обе могут провалиться:
  - *во времени*: сделки разбиваются на отрезки. Если весь результат сделан
    одним удачным периодом, это видно, а не усредняется;
  - *к параметрам*: та же логика прогоняется по сетке из 96 наборов порогов.
    Прибыль только при одной точной настройке — признак подгонки; широкое
    плато прибыльных настроек — признак, которому можно доверять.

**Надёжность данных**
- Каждая серия свечей проверяется на пропуски, дубли, нарушения порядка,
  битые значения и устаревание ленты. На подозрительных данных новый сигнал
  **не выдаётся** — испорченная свеча сдвигает все индикаторы, и результат
  выглядит совершенно нормально.
- Открытые позиции при этом всё равно доводятся до конца: бросать их из-за
  сбоя ленты нельзя.
- Запросы к бирже — с ретраями, экспоненциальной паузой и переключением на
  зеркала. Молчаливая остановка ценового цикла хуже ошибки: сигналы перестают
  закрываться, и трек-рекорд незаметно замерзает.

**История**
- Все закрытые сигналы помечены: <b>✓ Успешный</b>, <b>✗ Неудачный</b> или <b>○ Истёк</b>.
- Рядом с каждым — заявленная в момент выдачи вероятность, чтобы можно было
  сверить обещание с фактом.
- Сводка калибровки: средняя заявленная вероятность против фактического результата.

**Сайт**
- Карточки активных сигналов с живой ценой, прогрессом между стопом и тейком
  и текущим P&L в единицах риска.
- Обзор рынка: состояние индикаторов по каждой монете.
- История всех закрытых сделок, включая убыточные и истёкшие.
- Статистика: живой результат рядом с бэктестом + описание методики.
- График со свечами и отмеченными уровнями входа/стопа/тейка.
- Живое обновление через SSE.

## Сайт работает сам, без сервера

Дашборд опубликован через **GitHub Pages** и не требует ни хостинга, ни
запущенного процесса:

- **GitHub Actions по расписанию** (заявлено ежечасно) забирает данные с
  Binance, прогоняет ту же логику, закрывает дошедшие до стопа/тейка сигналы и
  коммитит результат в `data/*.json`.
- **Pages отдаёт статическую страницу**, которая читает эти JSON.
- **Цены в карточках** страница берёт с Binance напрямую из браузера, поэтому
  они двигаются в реальном времени, а не раз в час. Если браузер не может
  достучаться до биржи, показывается снимок с последнего скана — и об этом
  прямо написано рядом.

### Честно про расписание: cron на GitHub здесь почти не работает

Измерено на этом репозитории за первые 9.5 часов жизни workflow:

| Расписание | Слотов | Сработало |
|---|---:|---:|
| `*/15` (каждые 15 минут) | ~33 | **1** |
| `5,35` (дважды в час) | 2 | **0** |

Все остальные прогоны были от пушей. GitHub отбрасывает частые cron-расписания,
поэтому просить чаще — значит получать реже. Сейчас стоит `4 * * * *`:
ежечасно — это и максимум полезного (новые сигналы решаются на закрытых часовых
свечах), и форма расписания, у которой больше шансов. Единственный сработавший
прогон пришёлся ровно на начало часа, но это одно наблюдение, а не
закономерность, поэтому **сайт не обещает частоту — он показывает измеренный
возраст данных**. Старше 150 минут (два пропущенных часа) — вместо обычной
плашки предупреждение.

Пропущенный час стоит упущенных сигналов, но не ошибок: скан всегда читает
свежайшую закрытую свечу, а открытые позиции закрываются по истории свечей —
записанный результат сделки одинаков, заметили её вовремя или через пять часов.

Если нужна настоящая ежечасная надёжность, вариантов ровно три: смириться;
внешний бесплатный cron, дёргающий `repository_dispatch` (нужен токен, который
создаёте вы); или крошечный постоянно работающий хост. Гонять Actions
непрерывным job'ом я сознательно не стал — это уже похоже на использование
раннеров как бесплатного сервера, и рисковать за это аккаунтом не стоит.

Побочный эффект, который дороже, чем кажется: история сигналов лежит в
git-коммитах. Её нельзя переписать задним числом незаметно.

Тот же код работает и за Node-сервером (`npm start`) — режим определяется
автоматически, настраивать ничего не нужно. Под сервером появляются живой
поток SSE и кнопки ручного запуска.

### Что нужно включить один раз

В **Settings → Pages** источником должен быть `main` / корень репозитория.
После этого сайт доступен по адресу вида `https://<логин>.github.io/<репозиторий>/`.

## Другие проверки из GitHub

Если под рукой только телефон, локально ставить ничего не нужно — проверки
живут в GitHub Actions, а результат читается прямо в приложении GitHub.

**Проверка на живых данных биржи.** Вкладка **Actions** → workflow
*«Проверка на живых данных биржи»* → **Run workflow**. Можно выбрать источник,
таймфрейм и список монет. Через несколько минут в **Summary** появится отчёт:
связь с биржей и какой хост ответил, качество данных по каждой монете, бэктест
и обе проверки на устойчивость. Тот же отчёт сохраняется файлом `report.md` во
вкладке артефактов.

Запускается ещё и по расписанию, раз в неделю — чтобы видеть, держится ли
результат со временем.

**Глубокий анализ.** Вкладка **Actions** → workflow *«Глубокий анализ»* →
**Run workflow**. Можно задать глубину истории (по умолчанию 8000 часовых
свечей на монету — около года) и долю выборки для подбора настроек. Работает
несколько минут: качает историю постранично, прогоняет стратегию и считает
детальную статистику. Результат появляется на вкладке **«Аналитика»** на сайте
и в **Summary** прогона. Раз в неделю запускается сам.

**Тесты** гоняются сами на каждый пуш и в каждом PR, там же во вкладке Actions.

Это и есть способ проверить адаптер Binance на реальном соединении: раннеры
GitHub видят биржу, среда разработки — нет.

## Запуск локально

```bash
npm install
npm start
```

Откройте <http://localhost:3000>.

Работает сразу на живых данных Binance — ключи API не нужны, ордера не
выставляются, используются только публичные endpoint'ы.

Если `api.binance.com` заблокирован в вашем регионе или сети:

```bash
BINANCE_BASE_URL=https://data-api.binance.vision npm start
```

Демо без сети (синтетические данные, сайт предупреждает об этом баннером):

```bash
COINSCOPE_SOURCE=synthetic npm start
```

Бэктест из командной строки:

```bash
npm run backtest
```

Проверка стратегии на устойчивость (занимает пару минут — прогоняется вся сетка):

```bash
npm run validate
```

**Наполнить историю сразу.** Свежий сигнал идёт к стопу или тейку часами, поэтому
на новой установке история пуста. Реплей прогоняет прошлые свечи через ту же
логику выдачи и закрытия:

```bash
npm run replay
```

Такие сигналы помечены как «реплей», в **живой** трек-рекорд не попадают
(их никто не публиковал в реальном времени), но учитываются как доказательная
база для оценки вероятностей — наравне со сделками бэктеста.

Всё через переменные окружения:

| `BINANCE_BASE_URL` | `https://api.binance.com` | Зеркало, если основной хост закрыт |
| `COINSCOPE_SYMBOLS` | 8 монет | Список пар через запятую |
| `COINSCOPE_TIMEFRAME` | `1h` | Рабочий таймфрейм |
| `COINSCOPE_HTF` | `4h` | Старший ТФ для фильтра тренда |
| `COINSCOPE_MIN_SCORE` | `60` | Порог публикации сигнала |
| `COINSCOPE_MIN_ADX` | `20` | Ниже — считаем флэтом и молчим |
| `COINSCOPE_ATR_STOP` | `1.5` | Стоп = ATR × это |
| `COINSCOPE_RR` | `2` | Тейк = риск × это |
| `COINSCOPE_EXPIRY_BARS` | `24` | Через сколько баров сигнал истекает |
| `COINSCOPE_SCAN_SEC` | `60` | Период поиска новых сигналов |
| `COINSCOPE_PRICE_SEC` | `10` | Период опроса цен и проверки стоп/тейк |
| `COINSCOPE_MIN_PROB_SAMPLE` | `15` | Минимум похожих сигналов для показа вероятности |
| `COINSCOPE_FEE` / `COINSCOPE_SLIPPAGE` | `0.0005` | Комиссия и проскальзывание за сторону |
| `COINSCOPE_MAX_GAP_RATIO` | `0.01` | Доля пропущенных свечей, выше которой торговать нельзя |
| `COINSCOPE_MAX_STALE_BARS` | `3` | На сколько свечей лента может отставать |
| `BINANCE_BASE_URLS` | — | Свои зеркала через запятую, пробуются первыми |
| `COINSCOPE_HISTORY_BARS` | `8000` | Глубина истории для глубокого анализа, свечей на монету |
| `COINSCOPE_HOLDOUT_RATIO` | `0.7` | Доля истории под подбор; остальное — проверка |
| `COINSCOPE_MIN_BUCKET` | `25` | Меньше сделок в группе — не считается доказательством |

## Как считается результат

- **R** — результат в единицах риска. +1R = заработали столько, сколько рисковали.
- Вход по закрытию сигнальной свечи; исход определяется только по следующим свечам.
- Если свеча задела и стоп, и тейк — засчитывается **стоп**. Порядок движения
  внутри свечи неизвестен, и предполагать выгодный — значит врать себе.
- Сигнал, не дошедший ни до одного уровня за `expiryBars`, закрывается по рынку
  и всё равно попадает в статистику.
- Одна открытая позиция на монету.

### Откуда берётся вероятность успеха

Это **не прогноз модели**, а измеренная доля успешных среди похожих завершённых
сигналов: тот же таймфрейм и диапазон score, по возможности та же монета и
направление. В доказательную базу входят сделки бэктеста и уже закрытые сигналы.

Если похожих сигналов меньше `COINSCOPE_MIN_PROB_SAMPLE`, сравнение расширяется
по шагам (та же монета → то же направление → любой score), и каждый шаг явно
подписан в карточке. Если даже так данных не хватает — вместо числа написано
«нет оценки». Рядом всегда стоит доверительный интервал Уилсона и размер
выборки, а оценка **замораживается на момент выдачи**, чтобы историю нельзя
было задним числом переписать.

### Детальная статистика и почему она устроена так

Вкладка **«Аналитика»** — это диагностика, а не витрина. Сделки режутся по
score, направлению, монете, силе тренда, RSI, объёму, волатильности,
удалённости от EMA200, торговой сессии и дню недели. Задача каждой нарезки —
показать, где логика не работает, а не найти красивую цифру.

Такая нарезка опасна, и вот чем: если разделить любые данные на сорок групп и
проверять каждую на уровне 5%, две группы будут выглядеть «значимыми» просто
по построению. Поэтому:

- **Никаких голых процентов.** Каждая группа показана с доверительным
  интервалом — винрейт по Уилсону, средний R по стандартной ошибке. Интервал и
  есть честная ширина числа.
- **Считается цена случайности.** Рядом с каждой нарезкой написано, сколько
  групп проверено и сколько «значимых» дала бы чистая случайность. Находкой
  считается только превышение над этим числом.
- **Есть контрольная нарезка.** День недели включён намеренно: осмысленной
  связи там быть не должно. Если «связь» находится и там — это калибровка того,
  насколько врёт случайность на этой выборке.
- **Малые группы не считаются доказательством.** Меньше 25 сделок — строка
  показывается бледной и никогда не помечается значимой.
- **Подбор настроек проверяется на невиданных данных.** Лучший набор
  параметров выбирается на первых 70% истории и оценивается на последних 30%,
  которых подбор не видел. Разрыв между двумя числами — это измеренный размер
  подгонки. Подобранный набор **не применяется автоматически**: выбрать
  максимум и объявить его настройкой — ровно то, от чего эта проверка защищает.

Отдельно считается **калибровка**: из сигналов, которым сайт написал «60%»,
выиграли ли примерно 60%. Это проверка честности самого числа рядом с сигналом,
и считается она по реально выданным сигналам, а не по бэктесту.

И **ход цены** (MFE/MAE): убыточная сделка не пошла никуда или дошла почти до
цели и развернулась? Это разные проблемы. Одна лечится входом, другая выходом,
а винрейт не различает их вовсе. У этой метрики есть честное ограничение: у
выигрышных сделок она обрезана целью — сделка там заканчивается, и куда цена
пошла бы дальше, из этих данных не узнать. Поэтому информативны числа по
убыточным, а вопрос «а если цель подвинуть» решается перезапуском стратегии с
другой целью, а не экстраполяцией.

## Тесты

```bash
npm test
```

231 проверка в девяти наборах. Главный из них — `strategy.test.mjs`: он
перепроверяет решения движка на сотнях баров, подавая ему только доступную на
тот момент историю, и требует, чтобы вердикт не менялся при раскрытии будущего.
Бэктест без этой гарантии бесполезен.

## Архитектура

```
server/
  config.js       параметры и пороги (всё переопределяется env)
  indicators.js   EMA, RSI, MACD, ATR, ADX/DMI, Bollinger — чистые функции
  strategy.js     конфлюэнс-движок: score, направление, уровни
  backtest.js     прогон по истории + учёт комиссий + статистика
  tracker.js      живой цикл: сканирование и доведение сигналов до конца
  probability.js  оценка вероятности по фактическим исходам + интервал Уилсона
  dataQuality.js  аудит свечей: пропуски, дубли, порядок, устаревание
  validate.js     устойчивость во времени и к параметрам (анти-подгонка)
  replay.js       прогон прошлых свечей через ту же логику (наполнение истории)
  staticRun.js    прогон без сервера и без БД: пишет data/*.json для Pages
  db.js           SQLite: сигналы, исходы, бэктесты (только для локального сервера)
  sources/        binance.js (боевой) и synthetic.js (офлайн) за одним интерфейсом
index.html        дашборд (Pages отдаёт его из корня)
assets/           стили и клиент — один код для статики и для сервера
data/             JSON, который коммитит плановый скан; его читает сайт
```

## Ограничения

- Стратегия одна — трендследящая. На затяжном флэте она молчит, и это
  сознательно: лучше не дать сигнал, чем дать плохой.
- **Измеренное преимущество отрицательное** (см. раздел выше). Пока это так,
  сигналы — материал для проверки гипотез, а не для торговли.
- **Окно истории короткое.** ~500 часовых свечей это около 20 дней, то есть
  один режим рынка. На таком отрезке нельзя ни подтвердить стратегию, ни
  окончательно её похоронить. Следующий честный шаг — постраничная загрузка
  klines за куда более длинный период и повторный прогон проверок.
- Адаптер Binance работает в GitHub Actions (реальный скан прошёл: 8 монет,
  500 свечей, 0 пропусков). В среде разработки биржевые API закрыты политикой
  сети, поэтому там используется синтетический источник.
  Он нужен только для разработки и тестов и ничего не говорит о реальном рынке.
- Нет исполнения ордеров. Только сигналы.
