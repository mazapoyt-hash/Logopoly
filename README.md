# Logopoly Chat

Онлайн-чат поддержки для сайтов — открытый клон ядра [Talk-Me](https://talk-me.ru).
Встраиваемый виджет для посетителей + панель оператора с общением в реальном
времени. **Один отдел поддержки обслуживает сразу несколько сайтов (брендов)**,
диалоги в панели разложены по сайтам.

## Возможности

**Мультисайтовость (несколько проектов в одном отделе)**
- Отдельная сущность «сайт»: своё название, цветовая метка, домен и **свой ключ виджета**.
- Инбокс сгруппирован **разделителями с названиями сайтов**: под каждым — диалоги
  этого сайта, в заголовке счётчик непрочитанных и общее число; группы сворачиваются.
- Панель руководителя (**⚙ Настройки**): добавление/переименование/архивирование
  сайтов, копирование готового кода виджета, назначение сотрудникам сайтов галочками.
- Оператор видит и может отвечать **только на своих сайтах** — ограничение на
  сервере: чужие диалоги не приходят в инбокс, их нельзя открыть, ответить в них
  или увидеть предпросмотр печати.
- Изменение доступов применяется **на лету**, без перезахода оператора.
- Присутствие «оператор на связи» считается **по каждому сайту отдельно**.

**Роли**
- `admin` (руководитель отдела) — видит все сайты, управляет ими и составом команды.
- `operator` — работает только с назначенными сайтами.
- Первый вошедший оператор автоматически становится руководителем.

**Виджет на сайте (сторона посетителя)**
- Плавающая кнопка и окно чата с индивидуальным дизайном, настраивается через `data-*`.
- Обмен сообщениями в реальном времени (Socket.IO).
- Индикатор «оператор на связи / офлайн».
- Pre-chat форма (имя, email), сохранение диалога между визитами (localStorage,
  отдельная личность посетителя на каждом сайте).
- Оценка диалога звёздами после завершения.
- Заблокированному посетителю виджет не показывается.

**Панель оператора**
- Инбокс с непрочитанными, последним сообщением и временем.
- Переписка в реальном времени, история диалога.
- **Живой предпросмотр — оператор видит текст посетителя ещё до отправки**
  (фирменная фича Talk-Me).
- Карточка посетителя: сайт, страница, источник трафика/UTM, поисковый запрос,
  браузер, ОС, устройство, гео (по IP), IP, первый визит.
- Редактирование контактов, категория, заметки оператора, блокировка.
- Шаблоны быстрых ответов (общие и личные, опционально привязка к сайту).
- Статусы оператора (в сети / отошёл / не в сети).
- Завершение диалога, назначение оператора.

## Технологии

- **Backend:** Node.js, Express, Socket.IO
- **Хранилище:** SQLite (better-sqlite3), файл в `data/chat.db`
  (путь переопределяется через `LOGOPOLY_DATA_DIR`)
- **Frontend:** ванильный HTML/CSS/JS, без сборки

## Запуск

```bash
npm install
npm run seed     # опционально: 8 демо-сайтов и примеры шаблонов
npm start
```

Затем откройте:
- Демо-сайты с виджетами: <http://localhost:3000/demo/>
- Панель оператора: <http://localhost:3000/operator/>

### Как проверить сценарий с несколькими сайтами

1. `npm run seed` — создаст 8 демо-брендов.
2. Откройте <http://localhost:3000/operator/>, войдите под любым именем —
   вы станете руководителем и увидите все сайты.
3. Откройте <http://localhost:3000/demo/>, зайдите на 2–3 разных бренда в
   отдельных вкладках и напишите из чата на каждом.
4. В панели диалоги окажутся под разделителями своих сайтов.
5. **⚙ Настройки → Сотрудники** — снимите/поставьте галочки сайтов у сотрудника:
   его инбокс изменится сразу.

## Тесты

```bash
npm test
```

Два end-to-end набора (40 проверок): базовый чат-флоу и мультисайтовая модель с
изоляцией доступа. Каждый набор поднимает свой сервер на отдельном порту и
временной БД.

## Встраивание на свой сайт

Код для конкретного сайта копируется в **⚙ Настройки → Сайты → «Код»**:

```html
<script src="https://ВАШ-ХОСТ/widget/widget.js"
        data-site="st_КЛЮЧ_САЙТА"
        data-title="Поддержка"
        data-subtitle="Отвечаем быстро"
        data-accent="#6d5efc"></script>
```

Без `data-site` виджет привяжется к первому (основному) сайту.

## Ограничения и дорожная карта

**Важно:** аутентификация пока демо-уровня — оператор идентифицируется своим id
без пароля, а админ-эндпоинты проверяют роль по заголовку `x-operator-id`.
Перед боевым использованием это нужно заменить на реальные сессии/пароли.

Дальше: омниканальность (Telegram/WhatsApp/VK/Email — поле `channel` уже заложено),
чат-боты и ИИ-ассистент (тип отправителя `bot` заложен), триггеры-автоприглашения,
аналитика по сайтам (источники, время ответа, оценки, нагрузка операторов),
реальный geo-IP, передача диалога между операторами.
